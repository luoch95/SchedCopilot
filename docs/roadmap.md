# Schedule Copilot 四阶段路线

## 第一阶段：本地业务闭环（已完成）

围绕注塑车间设备故障和模具换型场景，完成规则排程、故障影响分析、候选方案比较、甘特图、证据展示和人工发布。确定性规则负责约束校验和候选结果，AI 只做辅助解释。

## 第二阶段：多 Agent 协作增强（进行中）

按 [四 Agent 实现需求](agent-implementation-requirements.md) 的 V1.1 基线，开发数据校验 Agent、排产执行 Agent、评估 Agent 和解释 Agent，通过结构化共享状态和编排器动态协作，不固定串行。增加结构化报告、证据逐条引用、运行 trace、模型成本统计、真实模型 API 联调和失败降级。

当前四个角色、确定性动态编排、API/前端及真实模型适配均已实现。模型调用各角色工具并基于证据筛选解释重点，规则负责计算和独立校验；页面显示模型调用及回退状态。角色契约沿用 V1.1，工作流扩展见 V1.2。剩余重点为固定多案例评测、持久化运行审计和完整浏览器验收。详见[模型接入说明](live-model-integration.md)。

## 第三阶段：实时制造事件接入

接入 MES/ERP 或设备事件流，处理重复、乱序、延迟和过期事件，支持多故障、紧急插单、班次、物料和模具保养等业务信息。所有变更仍由 Agent 建议、规则校验、员工确认。

## 第四阶段：可演示的制造业应用

补充多案例评估、Agent 单体与协作效果对比、审计和可观测性，增加认证、云端部署和面试演示环境。重点验证迁移能力、解释能力和人机协同流程。

项目不以 CP-SAT、数学优化器或追求理论最优解为主线。排程结果由可解释规则和校验器保证，Agent 负责证据读取、分析、协调和解释。

### 目标与职责边界

业务员申请插单并查看宏观影响；排产计划员查看详细排程、复核调整并人工发布。两个角色共用申请记录、排产计算及评估数据，业务员看到的是试排结果摘要。

主流程：角色选择 → 业务员填写申请 → 四 Agent 试排评估 → 查看影响摘要 → 提交领导审批 → 审批通过 → 排产员复核、调整并发布 → 业务员查看最终结果。

领导批准表示同意业务取舍，不等于正式发布。试排、提交审批和批准均不直接修改正式计划。审批、状态流转与发布由业务系统控制，Agent 不拥有审批或发布权限。
