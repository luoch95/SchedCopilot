# ADR 0003：React 前端与 FastAPI 后端分离

状态：已采用。取代 ADR 0002 的 Streamlit 主界面选型，保留规则排程、三 Agent、SQLite 和人工发布原则。

## 问题

方案需要同时展示甘特图、工序调整、订单交付、影响链和证据。Streamlit 对精细布局、甘特条标注及联动交互的控制有限；界面状态与 Python 页面重绘耦合。

## 决策

- 前端采用 React、TypeScript、Vite，位于 `frontend/`，独立使用 npm 锁文件、构建和交互测试。
- 后端采用 FastAPI，入口为 `sched_copilot.api:create_app`；后端源码、测试、依赖配置和锁文件统一放入 `backend/`，Python 依赖继续由 uv 管理。原有业务模块直接复用，不重新实现排程算法。
- 前端只通过 `/api` 读写业务数据。API 不接受客户端计算的候选排程，候选批次持久化到 SQLite，人工决定只提交批次 ID、候选 ID、操作、理由和幂等请求 ID。
- 编辑和试算携带事件版本与基线指纹；发布在存储事务中再次检查事件版本、计划指纹和排程约束。事件从 A 改为 B 再改回 A，旧候选仍不能发布。
- 时间传输使用带时区的 ISO 8601，界面统一按车间 UTC+08:00 显示；不依赖浏览器所在时区。
- 开发时 Vite 的 5173 端口代理 `/api` 到本机 8000；演示时先构建前端，再由 FastAPI 提供静态产物。代码和构建分离不意味着必须购买两台服务器。
- 沿用 `.data/decisions.sqlite3`，保留正式计划、事件与人工记录，只新增候选批次表。测试使用临时数据库。
- 默认数据库路径相对于仓库根目录固定，不随进程工作目录变化；前端产物默认定位到同级 `frontend/dist/`。独立 wheel 部署可用 `SCHED_DB_PATH`、`SCHED_FRONTEND_DIR` 显式配置路径。
- 迁移初期保留旧 Streamlit 入口；后续按 [ADR 0004](0004-module-boundaries.md) 移除旧实现、专用依赖和旧界面测试，Git 保留历史。

## 界面行为

候选方案默认平铺，共用时间范围与订单颜色。紫色描边表示设备转移，橙色表示仅调整时间。指标用颜色与文字双重标注；工序与订单对照突出方案差异。证据与假设使用同一 CSS Grid，逐行对齐。编辑未保存输入即清除旧候选与报告；过期版本要求重新载入。

## 边界

这是本地单用户演示架构，不包含认证、任务队列、实时设备接入或多故障叠加。底层仍是10月19日13:00固定快照，更改故障时间不改变报工状态。API 多 Agent 仍需后端模型配置；离线模式是明确标注的脚本演示。候选批次目前保留在本地数据库，尚无自动清理策略。

## 验证

后端覆盖原业务测试和 HTTP 流程，包括旧数据库复用、未知恢复、恢复入口、跨进程候选读取、候选篡改拦截、A→B→A 事件版本和重复发布。前端覆盖方案平铺、设备转移描边、证据网格、人工选择发布、草稿清除旧结果和过期版本处理。浏览器视觉检查受当前工具连接错误限制，不能用组件测试代替视觉核验。
