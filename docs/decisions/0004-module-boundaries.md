# ADR 0004：按业务职责分层，并检查依赖边界

状态：已采用。补充 ADR 0003 的内部模块设计。

## 问题

目录层面的前后端分离没有解决内部耦合：原 `api.py` 同时编排业务、处理 HTTP 和编解码候选；原 `App.tsx` 同时处理网络、状态、表单和各区域布局。继续直接追加功能会扩大修改范围，降低可测试性。

## 决策

后端划分 API、application、domain、infrastructure、agents 和 scenarios，统一由组装入口注入具体实现。业务用例使用类型明确的命令、结果和端口，不依赖 FastAPI、Pydantic 或 SQLite 实现。HTTP 路由与表现映射不运行排程算法。

前端以 app、features、shared 组织；功能提供公共 index 入口。工作台控制器集中维护版本、草稿和候选失效，展示组件仅接收数据与回调。方案比较进一步拆出指标、工序、交付、影响链和证据组件。测试数据与样式也按职责分离。

后端通过 AST 依赖测试，前端通过 TypeScript AST 检查脚本，将导入方向与网络访问边界纳入 CI。完整结构和新增功能规则见 [代码结构说明](../code-structure.md)。

## 保留的行为与简化

HTTP 地址和启动命令、原数据库、候选记录、版本校验和人工发布行为保持兼容。发布最终校验与写入仍处于同一事务；恢复选择策略移到用例层，但存储在事务中执行该选择，避免竞态。HTTP 错误新增稳定 code，detail 保持原有可读格式。

移除旧 Streamlit 实现、对应旧界面测试及专用依赖，历史代码由 Git 保留。现行 React 与 API 测试覆盖恢复、草稿清除、过期候选、人工拒绝、发布及网络重试幂等。没有引入微服务、消息总线、通用仓储基类或新状态管理库。

## 限制

分层是维护约束，不意味着已具备生产上线能力。数据库仍是本地 SQLite，业务仍是13:00固定快照。真实设备、用户认证、队列和真实模型联调不属于此次重构；浏览器视觉核验仍受工具连接限制。
