# ADR 0002：本地优先的多 Agent 最小版本

状态：已采用。取代 ADR 0001 中尚未确定的首版界面和接口选型。

后续变更：Streamlit 主界面选型已由 [ADR 0003](0003-react-fastapi.md) 的 React + FastAPI 替代。本文保留首版决策背景。

## 决策与理由

- 使用 uv 管理包、隔离环境、锁文件和构建，Python 3.12 作为开发与 CI 基线。
- 第一版使用 Streamlit + Plotly，省去独立前端和 API 部署；业务核心位于独立 Python 包中，后续可由 FastAPI 复用。
- 使用 SQLite 保存当前计划、当前事件与人工决定。发布采用事务、计划指纹检查和幂等请求 ID；单用户演示不引入 PostgreSQL。
- LangGraph 将生产计划与设备资源角色并行执行，再汇合到决策协调角色。各角色独立上下文，只开放只读证据工具，没有发布工具。
- 无密钥时使用明确标注的脚本模拟流程；配置兼容工具调用的 API 后启用真实 Agent。不能将离线模拟结果描述为模型推理。
- 先使用最早交期规则生成两种策略候选，独立校验设备资格、设备互斥、工序先后、故障窗口和固定工序。CP-SAT 留待后续里程碑。
- 前端、Agent、工具和存储运行在本地，不部署云端。模型调用使用外部 API。

## 人工介入

候选方案生成后必须在界面输入理由并选择发布或拒绝。发布前核对事件、基线版本与约束。工具、页面重绘和 Agent 输出都不能自动发布。

## 取舍与限制

Streamlit 适合小规模演示，复杂拖拽需要后续组件或界面升级。首版甘特图支持悬停与缩放，不支持拖拽。

当前没有实际设备连接、用户身份认证、实时事件流或生产级审计保护。故障发生在固定仿真时刻；不支持加工中故障。API 模式限制模型输出、请求超时、重试及工具循环次数，但仍应由调用方设置供应商预算。

## 后续

补充自定义事件、事件去重/乱序处理、执行反馈、CP-SAT 与人工试排；用固定评测集比较单 Agent 和多 Agent 的收益与成本。
