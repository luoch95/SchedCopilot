# 首个案例：车削设备故障

所有数据均为仿真，时间采用 UTC+08:00。日期为 2026-10-19；工作日历连续，不建模午休或夜班。

## 快照

13:00 时，M1 刚完成订单 O1001 的精加工，尚未开始 O1002。M1 故障，预计 17:00 恢复。此前工序已完成并固定。

| 订单 | 名称 | 交期 | 工艺与基线计划 |
| --- | --- | --- | --- |
| O1001 | 泵轴组件 | 15:00 | M1 车削 08:00-10:00 → M3 铣削 10:00-12:00 → M1 精加工 12:00-13:00 |
| O1002 | 阀体组件 | 18:00 | M1 车削 13:00-14:30 → M3 铣削 14:30-16:30 |
| O1003 | 联轴器 | 16:00 | M2 车削 08:00-10:00 → M2 精加工 10:00-11:00 |
| O1004 | 法兰盘 | 19:00 | M3 铣削 16:30-18:00 → M2 精加工 18:00-19:00 |
| O1005 | 调节杆 | 21:00 | M1 车削 14:30-16:00 → M1 精加工 16:00-17:00 |

M1、M2 都具备车削与精加工能力。M3 具备铣削能力。首版假设合格设备加工时长相同，且不提前基线任务的开始时间。

## 可手工核对的结果

直接受影响：O1002-OP1、O1005-OP1、O1005-OP2，共 3 道工序。

等待原设备恢复：O1002 车削移到 17:00-18:30，铣削移到 18:30-20:30；O1005 两道工序顺延至 18:30-21:00。只有 O1002 延期 150 分钟，移动 4 道工序，全部订单最晚 21:00 完工。

O1004 可以继续使用 M3 的 16:30-18:00 时段，不需要等待 O1002。设备竞争的影响取决于具体时段，不能把故障后的所有任务一律顺延。

允许转移：O1002 和 O1005 的车削/精加工转至空闲且合格的 M2，其他任务保持原时段。没有延期，移动 3 道工序，全部订单最晚 19:00 完工。

这里的规则结果不包含换型损失、工装和人员占用。转机在这些假设下表现较好，不能据此声称真实工厂必然应转机。

## 指标口径

- 延期订单数：最后一道工序结束时间晚于订单交期的订单数量。
- 累计延期分钟：逐订单计算 max(0, 完工时间 - 交期) 后求和。
- 移动工序数：相对同一基线，开始时间或设备分配变化的工序数量。
- 最晚完工时间：所有工序结束时间的最大值，不等同于设备利用率。

## 演示步骤

1. 启动应用，查看当前计划、故障事件和候选指标。
2. 切换候选方案，在甘特图悬停查看工序和时间。
3. 运行离线分析，查看三个角色各自获得的证据；该模式无模型调用。
4. 输入理由后选择“暂不发布”，检查计划版本保持不变。
5. 改为“确认发布”，检查计划版本递增，刷新后仍可查看决定记录。
