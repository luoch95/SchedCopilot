# 范围与验收标准

## 用户与任务

主要用户是生产计划员。设备故障后，用户需要知道哪些订单受影响、有哪些调整选项、各选项的代价，以及结论依据。

第一版以单个计划员的本地演示为目标。审批记录用于展示流程，不宣称提供生产级权限控制。

## 首个业务案例

- 使用固定、可重复的仿真数据：3 台设备、5 个订单，每个订单 2 至 3 道工序。
- 数据包含工序先后、设备资格、在不同设备上的加工时长、订单交期。
- 首版采用连续可用的工作时间，不引入班次；时间使用统一的时区约定。
- 故障事件包含设备、发生时间、预计恢复时间、来源和接收时间。
- 首个故障案例限制为设备发生故障时没有正在加工的工序，避免默认为可随意中断、恢复或迁移在制工序。
- 已完成与已开工工序固定；重排仅修改尚未开始的任务。
- 预计恢复时间必须显式给出并标为假设；未知时请求人工补充，不输出伪精确方案。

这些简化应在界面和演示中明确呈现。后续通过独立案例引入加工中故障、班次、换型和物料。

## 决策流程

1. 展示已发布基线计划和数据快照。
2. 接收故障事件，保存来源和时间信息。
3. 标记直接受影响工序，计算后续工序和设备竞争导致的连锁影响。
4. 生成等待原设备恢复、转移至合格设备等候选方案；不可行的候选明确给出原因。
5. 比较订单延期、计划完工时间、被移动工序数等指标，并展示计算口径。
6. 展示推荐依据、约束、假设和方案取舍；不预设存在同时改善全部指标的方案。
7. 用户接受、拒绝或修改候选方案。确认发布前重新校验约束与基线版本。
8. 保存新计划、来源事件、方案差异、确认记录和人工理由。

## 功能验收

| 能力 | 可检查的结果 |
| --- | --- |
| 排程正确性 | 同一设备加工区间不重叠，满足工序先后、设备资格和故障不可用区间 |
| 执行边界 | 已完成和已开工工序保持固定，候选方案不直接覆盖已发布计划 |
| 方案比较 | 在同一数据快照下比较，指标有明确公式；不可行不等同于求解超时 |
| 人工确认 | 拒绝不改变计划；重复确认不重复发布；过期候选不能覆盖较新计划 |
| 解释追溯 | 关键数字可以定位到订单、工序、事件或计算结果，假设单独显示 |
| 甘特图 | 悬停显示任务时间、设备和状态；点击查看影响与来源 |
| 手动试排（后续） | 拖动后先校验并显示连锁影响，确认后才发布 |
| 可复现演示 | 固定输入可重复运行；展示输入、候选方案、选择理由和发布结果 |

## 实时能力的演进

先通过手动注入事件验证语义和状态流转，再实现模拟事件流。后续接入时处理重复、乱序、延迟和过期事件，并设置重排触发条件，避免每条状态更新都改变计划。

第一版不承诺毫秒级调度，也不接入真实工厂设备。

## 里程碑

1. M0：业务案例、数据字典、手工预期结果。
2. M1：数据模型、约束校验、规则排程和故障影响计算。
3. M2：候选方案比较、人工确认和计划版本管理。
4. M3：甘特图与端到端演示。
5. M4：引入 CP-SAT，并与相同输入下的规则结果比较。
6. M5：AI 解释与工具调用、模拟事件流、异常和过期数据处理。

每个里程碑先完成验收再进入下一阶段。需要时调整顺序并记录理由，不以堆叠技术数量衡量进度。
